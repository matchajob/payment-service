Cheap providers, without the integration pain.

Local acquirers often win on fees, installments and domestic cards, then lose on developer experience. The service absorbs each quirk, so your application never sees it.

Unsigned webhooks

We confirm each notification with the provider, then send you HMAC-signed events you can verify.

No idempotency

Every mutation takes an idempotency key. A retried request runs once and replays the stored answer.

Timeouts with unknown outcome

An unclear charge becomes a pending record that is reconciled with the provider. It is never charged twice.

Inconsistent declines

One decline-reason shape, whatever the provider sent back.

Unreliable notifications

Events go through an outbox with leases, scheduled retries and a dead letter state. At least once, in order.

No entitlement model

Every event carries a full snapshot and an entitled flag we compute. Your app never derives it.

One lifecycle for API calls, cron and provider webhooks.

Four states and a table of allowed transitions, so a subscription never lands somewhere unexpected.

  1. Create. Your server creates a subscription and gets a hosted checkout URL back.
  2. Pay. The customer pays on the provider's page. The card is saved and the subscription becomes active.
  3. Renew. Charges run on the customer's anniversary, never early. Amounts come from your plan, never from a payload.
  4. Recover. A failed renewal enters dunning on a schedule you set. A successful retry pays for the period that failed, so the anniversary never shifts.
  5. Hear about it. Each change reaches your webhook as a signed event.

Built so money moves once.

Billing mistakes are the expensive kind. The guards are layered, and each one is covered by a test written before the code.

Two workers charge the same renewalThe subscription row is locked, then status and the unpaid period are re-checked before the provider is called.
A provider replays a charge attemptEvery charge carries a dedup key built from the subscription, the period and the attempt number.
A bug slips past the lockA database index allows at most one successful charge per subscription and period.
Your client retries a requestTwo-phase idempotency keys. The same key returns the same stored response, byte for byte.
Saving a card charges itCard capture only saves a token. It never charges.
