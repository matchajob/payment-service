# ADR 0015: The SDK is a hand-written client over the contract schemas

**Status:** Accepted, 2026-10-16
**Slice:** 23. job-platform's receiver (slice 15) is the first consumer.

## Context

v1 ships a fully typed TypeScript SDK. Tenants call the API through it and verify and parse outbound events with it. Every type has to come from `src/contract`, so the SDK cannot drift from the server. Three ways to build the client were considered:

- **A. Hand-written thin client over `fetch`.** One method per route. Requests are validated and responses parsed with the contract's zod schemas.
- **B. Generated from an OpenAPI document** produced from the contract schemas. Tenants that don't use TypeScript get a spec for free. The cost is a generator, its output, and a schema-to-OpenAPI step that must stay faithful to zod 4.
- **C. Hono's `hc` client.** Ruled out: it types against the route tree, so the package tenants install would depend on `src/api` and hono, which the layering forbids for anything published.

## Decision

**A.** The SDK is written by hand and imports only `src/contract` and zod.

- The contract schemas already exist, are zod-only and are published. A hand-written client is one thin layer over them, with no build step between the schema and the type the tenant sees.
- The surface is small: about ten routes and one event union. Generated code would be larger than the code it replaces and harder to review.
- Behaviour a generator doesn't give us would be written by hand anyway: idempotency keys generated by default, problem+json errors as a typed error, and HMAC plus timestamp verification of events.

## Consequences

- Every new tenant-facing route needs a matching SDK method, added by hand. A test enumerates the router's tenant-facing routes and fails when one has no SDK method, so forgetting is caught in CI, not by a tenant.
- SDK tests run the client against the real app, with `app.request()` injected as `fetch`. A contract change that breaks the client fails here.
- No OpenAPI document exists. If a non-TypeScript tenant appears, generate one from the contract schemas then. That adds a spec and does not replace the client.
